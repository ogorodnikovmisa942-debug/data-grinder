# Состояние плана функций (на 2026-10-08)

Источник: «Data Grinder — план функций: бесплатные (код) и платные (API)». Здесь — что сделано, где это в коде и что осталось.

## Размер колоды: по содержанию и качеству, а не по деньгам

Решение владельца 2026-10-08. Хорошая колода на учебник ≈ 500 карточек, тысячи не нужны.

- Цель считает `source_profile.deck_goal`: размер материала и его тип (учебник — знаки ÷ 2300, конспект — по пунктам), только **новое** относительно курса, множитель глубины (кратко 0,6 / стандарт 1 / подробно 1,4).
- Потолок одного материала — 600 карточек, потолок предмета — 750 (до множителя глубины; `PATH_MAX_CARDS_PER_SOURCE`, `PATH_COURSE_CARD_CAP`). Курс уже полон, а в новом материале есть своё — даётся минимум 20 лучших карточек из нового.
- Проверка на настоящей модели (целая книга «Судоустройство», 1,05 млн знаков): первой книгой — 455 карточек; второй после части в 150 карточек — 354 новых, всего 504; повторы старых вопросов — 7 из 354.
- Деньги размер колоды не меняют: `Budget` (аварийный потолок 60¢) только пропускает необязательные этапы, если запрос «зациклился».
- Качество: каждая карточка с цитатой из книги; неподтверждённые после проверки отбрасываются (в узле остаётся хотя бы одна), лишнее сверх цели обрезается по оценке важности (`card_quality.card_priority`), отчёт `stats.quality` (доля подтверждённых, вопросов на понимание, повторы). В прогонах: подтверждено книгой 100%, повторов 0.
- Выбор глубины и типа материала — в окне загрузки («Насколько подробно», «Что за материал»).

Цена книги в 450 страниц при потолке-тормозе: **≈ 22,4¢** (замер 2026-10-08: 455 карточек, 1378 фактов конспекта, 141 тема, 5,8 мин).
